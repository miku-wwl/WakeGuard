# WakeGuard alpha.4-rc.1：iQOO Neo9 Pro 手工验收指南

> **实验性预发布，未经 iQOO / OriginOS 实机验证。** 已知的“最近任务上滑后活动闹钟停止”问题仍然开放。本指南用于采集结果，不表示兼容性已经修复。

## 安装与准备

1. 从 [alpha.4-rc.1 GitHub 预发布页](https://github.com/miku-wwl/WakeGuard/releases/tag/v0.1.0-alpha.4-rc.1)下载 `WakeGuard-0.1.0-alpha.4-rc.1-arm64-v8a.apk`。
2. 点击 APK 安装或更新 WakeGuard。alpha.3 使用兼容的签名证书和更低的 `versionCode`；通常可直接更新。**不要先卸载 alpha.3，也不要清除应用数据。** 如果系统拒绝更新，请记录提示并停止，不要为安装而删除数据。
3. 在系统“应用信息”中确认版本为 `0.1.0-alpha.4-rc.1`、版本代码为 4。记录“关于手机”中的 Android 版本、OriginOS 版本和完整软件版本/构建号。
4. 打开 WakeGuard「设置 → 闹钟可靠性检查」，记录显示的精确闹钟、通知、锁屏全屏通知、电池优化、后台限制和前台服务状态。
5. **先不要调整自启动、电池或后台高耗电设置**，以当前配置完成基线测试。OriginOS 专有开关显示为“需用户手动检查”是预期行为。

## 测试步骤

### TC01 — 预定闹钟：移除任务后响铃

建立一个约两分钟后触发的一次性闹钟。在响铃前打开最近任务，上滑 WakeGuard 卡片，并确认卡片确实消失。记录闹钟是否按时响铃。不要仅凭最近任务界面关闭或桌面出现来判断卡片已移除。

### TC02 — 活动闹钟：移除任务后的播放状态

让闹钟实际开始响铃，确认当时有声音；打开最近任务，把 WakeGuard 卡片向上滑到**卡片实际消失**。保持紧急停止可用，按需最多观察 15 秒，避免不必要的长时间响铃。记录：

- 音频是否始终连续；是否立即停止；通知是否仍在；是否无需操作便自动恢复，以及大约多久恢复。
- 重新打开应用后，是否显示原来的活动事件；是否需要点「继续响铃」。
- 手工尝试最多三次（条件允许时），每次记录时间与结果。失败后优先安全停止。

以下结果必须分别记录：

- **连续播放**：上滑前后音频没有中断。
- **系统支持的自动恢复**：音频曾中断，之后没有用户操作便恢复；记录间隔。
- **用户确认恢复**：重开应用后活动事件仍在，但服务无法确认，用户点击「继续响铃」才尝试恢复。它不算连续播放，也不算自动恢复，更不能作为“上滑移除后不中断”的通过证据。
- **未恢复**：没有自动恢复，且重开后没有可继续的活动事件，或用户确认恢复仍失败。

**「继续响铃」现有行为：** 当 Room 中仍有 `RINGING`/`VERIFYING` 事件，但应用无法确认前台服务正在运行时，响铃页提供此按钮。点击后，应用会在平台允许时请求前台服务继续播放同一个事件；这只是用户确认的恢复尝试，Android 或 OriginOS 仍可能拒绝服务启动。若音频已经停止，先记录界面和通知状态，再决定是测试恢复还是立即紧急停止。该按钮不会把已结束事件重新激活。

### TC03 — 熄屏

闹钟响铃时按手机电源键关闭屏幕，确认声音和振动状态。结束后用紧急停止安全收尾。

### TC04 — Home 与 Back

在响铃页测试 Back 和 Home。Back 不应完成闹钟；Home 可以隐藏界面，但不应将活动事件记为已验证。重新打开应用并记录同一事件状态。

### TC05 — 实机摄像头

确认相机预览来自手机相机。按现有验证规则，在 12 秒窗口内把镜头对准洗手台/洗漱区域，观察是否能识别洗手池和牙刷或牙膏。不要改变模型或识别阈值。随时保留紧急停止路径。

### TC06 — 紧急停止

分别在响铃页（若可行）和相机验证页检查紧急停止。确认声音和振动立即停止，事件结果是“紧急停止/未验证”，统计页的成功数不增加。

### TC07 — OriginOS 设置对比（仅当 TC02 失败时）

先记录当前设置和基线结果。手工检查该固件实际提供的后台高耗电/后台运行、自启动和电池限制选项。**只有机主同意后**，才调整必要选项并重复 TC02；逐项记录具体开关和前后结果。最近任务卡片锁定不能单独证明普通上滑移除兼容。

不要把 Android 前台服务任务管理器的“停止”、系统设置中的“强行停止”或设备关机混作最近任务上滑测试；这些是不同的系统操作。

## TC02 失败后的诊断收集

1. 先记录最近任务操作后的音频、通知、重新打开后的页面和「继续响铃」按钮状态。
2. 若应用仍显示活动事件且测试不需要继续，使用应用提供的「紧急停止」；不要让测试闹钟无目的地持续响铃。紧急停止后再进入设置。
3. 打开「设置 → 闹钟可靠性检查 → 导出诊断日志」。系统分享面板只在用户点击后出现；**WakeGuard 不会自动发送**。选择由机主信任的接收应用并手动分享导出的 JSON 文件。
4. 记录导出时间、设备、Android/OriginOS 构建号，以及该文件对应的 TC02 次数。原始诊断文件留在应用私有缓存中，分享对象由机主选择。

导出会包含应用版本、Android 版本、厂商/机型、公开权限与电池/后台状态、活动及最近闹钟事件、服务状态、最近最多 400 条 WakeGuard 生命周期事件和可用的系统进程退出元数据。系统退出原因的自由文本描述会被省略/脱敏。导出不采集序列号、IMEI、Android ID、账户、联系人、位置、相片、相机帧、无关通知或其他应用日志。OriginOS 专有开关无法通过公开 API 查询，仍须手工记录。
